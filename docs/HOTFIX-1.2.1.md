# 1.2.1 拍摄与队列恢复修复

## 问题与修复

从 `fb4a847`（1.2.0 build 5）检查出以下可导致无法拍摄、无法保存或恢复异常的路径。没有用户设备日志或真机执行结果，不能断言它们覆盖该设备上的所有原因。

1. **首次按快门只弹相册授权，不拍摄。** 原 `capturePressed` 在相册权限未决定时请求权限并直接返回，授权回调也没有继续此次拍摄。现在先捕获并持久化原片/成片，再由持有任务的 worker 请求添加相册权限。拒绝权限会保留素材。
2. **编辑器返回后，合成队列一直等待。** 打开编辑器会设置 `captureBusy=YES`，关闭时只清除 `editorShown`，没有更新控件/worker。积累到 6 个任务后，普通照片快门会被队列上限禁用。现在等待相机会话重新启动，再在主线程更新控件并解除 worker 占用。
3. **资源恢复后快门仍禁用。** 内存压力暂停/温度/可用内存导致 `tick` 提前返回，未触发控件更新，即使压力已解除也不会重新评估快门。现在在调度判断前通知观察者，并在界面展示暂缓拍摄原因及恢复提示。
4. **视频快门规则不一致。** 已保存的 LIVE 设置把视频错误限制为最多 2 个待处理任务；UI 与拍摄入口对正在处理任务的判断也不一致。现在共用模式感知的准入函数，保留资源上限和重任务互斥。
5. **录像恢复记录过早标记为可处理。** 原实现开始录制前就写 `raw`。现在先写 `capturing`，仅在录制成功和恢复记录写入成功后改为 `raw`，避免重启后自动处理未完成录像。
6. **损坏的恢复 JSON 可能导致界面异常。** 增加字典类型和日期检查，未完整拍摄也刷新恢复列表。

拍照最终完成回调、串行原片落盘、恢复日志写入、释放快门的先后关系保留。没有把普通照片改为预览截图，也没有删除暂存来绕过队列上限。

- 版本：1.2.1，build 6；Bundle ID `app.markcam.camera`；arm64，iOS 16.5 起。

## 真机待验收

以下项目均待执行，不能视为已经通过：

1. 全新安装，允许相机，保持 LIVE 关闭。第一次按快门后应已有照片落盘；允许添加相册权限后同一张照片应自动保存，无需再拍一次。
2. 拒绝相册权限，确认待保存保留原片/成片；随后授权并对失败作品重试。
3. 打开水印/设置编辑器再退出，连拍至少 8 张（允许队列在间隔中处理）；任务应持续消化，不能到 6 张后永久锁住。
4. 队列上限、内存压力或严重发热时显示暂缓信息；条件恢复后应在下次定时检查重新启用快门。
5. LIVE 开关、前后镜头、视频→照片切换后分别拍摄；普通照片、水印、方向、闪光灯与倒计时均复测。
6. 录像中退后台/中断后检查恢复列表；未完成记录不应自动合成，完成记录应正常处理。
7. 备份后对测试恢复记录写入数组/无效日期等损坏 JSON，打开待保存不应崩溃。
8. Live Photo 动态资源与静态图的配对、声音、长按播放、相册保存和保留原片选项复测。
