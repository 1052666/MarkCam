## 本次实现
- **拍摄与后处理拆开**：原片及恢复记录落盘、拍摄回调结束后释放快门；水印、调色及相册保存进入单任务队列。每个作品保存自己的设置快照。
- **有限连续拍摄**：普通照片待处理上限为 6；Live 的接纳条件更保守（待处理数少于 2）。需等待单次系统拍摄/落盘完成，不是硬件级高速连拍。队列在最后一次拍摄后等待约 1.2 秒再启动，优先响应继续拍摄。
- **控制重型任务重叠**：同一时间只处理一个作品；Live/视频重型处理期间限制新拍摄。可暂停合成，原片留在“待保存”。
- **降低内存占用的实现**：Core Image 从文件读取并编码到文件；减少整图 UIImage/NSData 中间副本；水印透明画布最长边限制 2048px，保留原照片输出尺寸，极细文字可能较软。
- **资源压力处理**：读取可用内存，监听内存压力，按温度状态暂停/限制处理，并清理缓存。新增本地 `Documents/LastMemoryStatus.json` 诊断，不上传服务器。
- **中断恢复**：保留原片与阶段记录；返回前台恢复可执行任务，失败/不完整素材在“待保存”查看。相册写入结果不明确的任务不静默重复保存，需用户先核对相册再决定重试。

## 必须知道的限制
- “后台异步”指不在相机界面线程合成，不是切换 App 后可无限运行。离开前台停止派发新任务，短时系统后台时限只用于收尾；iOS 仍可挂起或终止进程。
- **没有实测峰值内存或帧率，不能保证其他 App 不再被系统回收。** 是否发生 jetsam、连续拍摄速度与资源改善仍需真机日志和复测判断。
- Core Image 文件渲染仍会使用 GPU/解码内存，普通照片单次渲染不能保证立刻中断。内存不足时可能停止处理，稍后在“待保存”重试。
- Live Photo 的配对播放、声音、方向以及缩放/超广角和录像兼容性均需复测；不因源码存在相关逻辑就宣称已验证可用。

## 建议优先复测
1. LIVE 关闭，普通照片连续点击 3～6 次，核对每次原片、成片数量与水印设置快照。
2. 队列上限、内存/温度提示出现时能否恢复，暂停和返回前台是否保留待处理素材。
3. 合成或保存时切后台/强制结束 App，重新打开后检查“待保存”和相册，先确认是否已保存再重试。
4. LIVE 开启，验证长按播放、声音、方向、水印与保留原片；再测试录像与 0.5×/1× 切换。
