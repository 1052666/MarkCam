# MarkCam 1.2.1（build 6）拍照恢复与连续拍摄测试版

本版对应快门变灰、点击无反应，以及连续拍照需要等待前一张处理的问题。IPA 的 Bundle ID 仍为 `app.markcam.camera`，最低 iOS 16.5；需自行重签。下载位于 [v1.2.1-rc.1](https://github.com/1052666/MarkCam/releases/tag/v1.2.1-rc.1)。

## 已修复的代码路径

- 资源不足时禁用快门后，即使合成队列仍不能启动，也会每秒重新评估拍摄条件。温度或内存恢复后自动启用，并显示具体等待原因。
- 从水印/设置编辑页返回时，刷新控件并清除队列的编辑占用状态；避免所有后续作品一直等待，积满后无法拍摄。
- 每张照片由独立 `MCPhotoCaptureProcessor` 持有设置快照、文件路径和回调状态。普通照片在曝光结束时释放快门，前一张 JPEG 返回或磁盘写入未结束时可接受下一张，避免两张回调互相覆盖。
- 快门、入口校验和后台队列使用一致的容量规则。视频不再因照片模式留下的 LIVE 设置错误地使用实况限制。
- 相册权限恢复后，仅自动恢复确认为权限失败的作品；上次保存结果不确定的 `saving` 记录仍需先检查相册。
- 短暂渲染内存不足会等待后重试，不再永久标记为失败。损坏的恢复设置先校验，避免在自动恢复时崩溃。
- 录像启动失败会释放占用；录制记录在结束并验证文件后才进入可处理状态。

## 连续拍摄与画质

- **普通照片最多两张在途**，在途照片与待处理记录共用六张容量预算。扫描期间可能保守地少接纳一张；不会为增加连拍数丢弃旧作品。
- 普通照片的水印/调色和相册保存继续在串行后台队列执行；快门不等待这些操作。开始新合成前留出 1.2 秒，让连续按快门优先。
- 每次拍照不再重复锁定曝光设备、更新全部预览连接和触发布局刷新。
- 没有水印、没有调色时直接复制完整原始 JPEG，不再解码并重新压缩，保留原始质量与 EXIF。
- 设置新增“连拍优先（弱光细节可能减少）”，默认开启：普通照片使用 AVFoundation 的速度优先策略，照片尺寸不变，但低光降噪与细节质量可能降低。关闭可恢复速度/画质平衡。Live Photo 始终使用平衡策略。
- LIVE、视频和重型合成保持互斥；本版是快速连续点按拍照，不提供长按无限连拍。
- 内存和温度限制继续生效，灰色快门会说明原因。处理能力、曝光时间、闪光灯和存储速度都会影响实际间隔。

Apple 说明速度优先可能牺牲画质：[photoQualityPrioritization](https://developer.apple.com/documentation/avfoundation/avcapturephotosettings/photoqualityprioritization)。可用内存属于实时建议值，不能缓存或视为系统不会终止 App 的保证：[os_proc_available_memory](https://developer.apple.com/documentation/os/os_proc_available_memory)。

## 自动验证与产物

GitHub Actions 对同一提交执行：

1. macOS 上运行实际照片处理器的交错回调与落盘测试，使用模拟的照片数据、真实 Foundation 文件操作；不访问摄像头。
2. Linux 上使用固定 SHA-256 的 iPhoneOS16.5 SDK、Clang/LLD 交叉编译所有 Objective-C 源码并生成 arm64 IPA。
3. 对四个照片回调逐个做正/负编译回归；运行共享 C 拍摄门控、恢复策略、布局和缩放测试。
4. 校验 IPA 内的版本、架构、回调实现地址、权限、文件结构，以及源码提交和 SHA-256。

具体结果和数量以该提交的 CI 与 Release JSON 报告为准。下载包中的 `build-report.json` 给出源码提交和 IPA SHA-256；`SHA256SUMS.txt` 校验 IPA、源码压缩包与各检查报告。

**尚未运行 iPhone 真机或 iOS 模拟器验收。** macOS 回调测试不能验证真实曝光回调的时序、相册权限弹窗、Live 播放或 UIKit 控件。没有测量帧率、快门间隔和峰值内存，也不宣称达到系统相机的速度。

## 真机复测

1. 用与旧版一致的签名身份/Bundle ID 覆盖安装，先导出模板并备份 Pending；不要先卸载旧版。
2. 关闭 LIVE 和倒计时，正常光线快速点按 6 次。核对每张照片、水印、时间及相册件数；等待队列清空后继续拍。
3. 打开水印编辑页再返回，重复上一步，确认后台保存与快门都恢复。
4. 开启调色和多层图片水印，再重复快速点按；比较连拍优先开/关的快门间隔、弱光画质和取景稳定性。
5. 在快门灰色时核对原因；队列清空或设备恢复后应自动解除。因内存阻塞的原片应保留并可继续处理。
6. 依次验证前/后摄、横/竖屏、闪光灯、倒计时取消、拒绝后恢复相册权限，以及录像启动失败。
7. 单独验证 Live 主照片+MOV 配对、水印和相册长按播放；切后台/强制退出后确认暂存可恢复，未知保存状态没有被自动重复提交。
